💾 windows-dev-machine-migration-notes - Back Up Your Windows Dev PC Safely

A simple, repeatable way to save everything important on a Windows development computer — passwords, project history and AI assistant settings — so you can move it all to a new machine without losing a thing. The whole routine is designed to be run by an AI agent that walks through each step for you.

📦 What This Project Is

Most people know how easy it is to back up an iPhone. You plug it in, everything is copied, and when you buy a new phone you restore from that copy and carry on as if nothing changed. A Windows development machine usually has no such safety net.

This project collects the notes, checklists and helper routines that recreate that iPhone-style experience for a Windows 11 development computer. Instead of guessing which folders matter, you follow one rehearsed sequence. The sequence is executed by an AI agent, which means it runs the same way every time, in the same order, without skipping a step because someone was tired at 11pm.

The result is a single, organised backup you can store on an external drive or in cloud storage, plus a matching restore path for the day you sit down in front of a brand-new PC.

🧰 What Gets Backed Up

Five categories cover almost everything a working developer machine holds:

🔐 Passwords and secrets

Access keys, environment files, tokens and other private values are kept in Bitwarden rather than scattered across folders. During a backup, the routine checks that everything sensitive lives in the vault, so the backup itself never carries a plain-text password file around.

🌿 Project history (git bundles)

Each code project is packed into a single portable bundle file. A bundle contains the complete history of a project — every commit, every branch — in one tidy file that can be restored on any machine, even one with no internet connection.

🤖 Claude Code state

The settings, preferences and session history used by the Claude Code assistant are captured so the tool picks up exactly where it left off after a move. No reconfiguring, no retraining yourself on where things were.

⚙️ Dotfiles and configuration

Shell profiles, editor settings, terminal themes and other small configuration files are gathered together. These are the files that make a computer feel like your computer.

📋 Installed software list

A record of installed applications and packages is saved through winget, Windows' built-in package manager. It becomes a shopping list for the new machine, so nothing is forgotten.

✅ Before You Begin

You do not need to know how to program. You do need a little patience and a few things in place:

  • A Windows 11 computer that you want to back up (Windows 10 also works for most of the routine).
  • A Bitwarden account, logged in and unlocked, so the vault can be checked.
  • Enough free space on an external drive or cloud folder for the backup files.
  • Roughly an hour of time when the computer can be left alone — larger projects take longer.
  • A quiet moment to read the checklist before starting, not during.

None of this changes anything on your system by itself. The routine only reads and copies; it does not delete files from your computer.

🔁 How a Backup Works, Step by Step

The routine is deliberately boring, and that is the point. Boring means predictable, and predictable means you can trust it.

  1. Preparation. The agent checks free disk space, confirms Bitwarden is unlocked, and makes a note of what is about to be copied.
  2. Secrets sweep. Anything that looks like a password, token or key is flagged. If it is not already in Bitwarden, it is moved there before anything is packed.
  3. Project packing. Every code folder is bundled into a portable archive. The bundles are named with a date so you can tell one backup run from another at a glance.
  4. Assistant capture. Claude Code settings and state are copied into the same dated folder.
  5. Configuration collection. Dotfiles and editor settings are gathered into a single tidy directory.
  6. Software inventory. The list of installed programs is exported so the new machine can be rebuilt from it.
  7. Verification. The agent re-opens the finished backup and checks that every expected folder and file is present and readable.
  8. Handover. You get a short summary: what was copied, how large it is, and where it lives.

Each step prints a plain-language message as it goes, so you always know where you are in the process. If something needs your attention, the run pauses and tells you rather than quietly carrying on.

🖥️ Restoring on a Fresh Windows Machine

Restoring is the mirror image of the backup, and it is the part most people worry about. The notes break it into calm, ordered stages.

First, the new PC is brought up to a working baseline: Windows updates applied, the package manager ready, and the saved software list used to reinstall the tools you actually use. Next, the dotfiles and configuration files are placed back so the desktop, terminal and editor feel familiar immediately.

After that, the git bundles are unpacked. Each project returns with its full history intact — branches, tags and commits all present — because a bundle is a complete snapshot rather than a loose copy of files. Claude Code state is restored alongside, so the assistant remembers your preferences from the first moment it opens.

Finally, Bitwarden is signed in and the vault supplies the credentials the restored projects need. Because secrets were never stored in the backup itself, nothing sensitive was ever sitting on a drive waiting to be misplaced.

🔐 Where Your Passwords Actually Live

This is the single most important design decision in the whole project, and it is worth understanding even if you never open a settings file.

The backup folder is designed to be shareable, copyable and storable without fear. That is only possible because it deliberately does not contain passwords. Everything secret lives in Bitwarden, which is protected by your master password and, ideally, two-factor authentication. The backup holds pointers and project data; the vault holds the keys.

The practical benefit is simple: if the backup drive is lost, stolen or accidentally uploaded somewhere public, you have not handed over your accounts. You have handed over some code history and a list of installed apps.

🧪 Rehearsed, Not Yet Used for a Real Move

Honesty matters more than marketing. The routine described here has been rehearsed end to end on a test machine — backup taken, machine wiped, restore performed, everything checked — but it has not yet been used for a real migration onto a brand-new computer.

That means you are looking at a well-exercised plan, not a battle-tested one. If you run it before the author does, your experience is genuinely useful. Note down anything that surprised you, and the checklist gets better for the next person.

Treat the first run on your own machine as a rehearsal too. Do a backup, restore it somewhere harmless, and confirm you are happy before you rely on it for a move that matters.

🛠️ Troubleshooting

The download page will not open

Check your internet connection and try a different browser. Corporate networks sometimes block download pages; a home connection usually resolves it.

Bitwarden is locked partway through

Unlock the vault and run the step again. The routine is designed to be restartable, so a pause does not ruin the whole backup.

A project bundle looks smaller than expected

Very large files are often excluded from project history on purpose. Check whether the project contains large media or data files that were never committed in the first place.

The run stopped with a message you do not understand

Copy the message exactly as written and search for it, or ask the AI agent to explain that specific line. The messages are written in plain language precisely so they can be looked up.

❓ Frequently Asked Questions

Do I need to know how to code to use this?

No. The routine is written to be followed, not modified. You read the steps, run them, and confirm the summary at the end.

How long does a backup take?

Usually between twenty minutes and an hour, depending on how many projects you have and how large they are.

Is this only for Windows 11?

Windows 11 is the main target. Most of the routine also works on Windows 10, though a few features behave differently.

Can I run it more than once?

Yes, and you should. Each run creates a new dated backup, so you build up a series of restore points rather than overwriting one fragile copy.

What happens to my old machine?

Nothing automatically. The routine only reads and copies. Wiping or resetting the old computer remains entirely your decision, made after you have confirmed the restore worked.

Where should I store the backup?

Two places is better than one. An external drive kept nearby plus a cloud folder covers the common failure cases without much effort.
